## 2. 처리 중 입력 규칙

> **아래 처리 중 표시는 멈춤이 아닙니다.** 표시가 사라지고 다음 행동 안내가
> 바뀔 때까지 같은 PHS2나 제품을 다시 스캔하거나 F3/F4를 반복하지 마세요.

현재 소스의 표준 PHS2/F4/F3 경로는 다음 문구를 그대로 표시합니다.

| 작업 | 화면의 처리 중 문구 |
| --- | --- |
| PHS2 접수·검증 | `현품표 저장 · 중앙 확인 중` |
| F4 준비 | `제품 교체 · 중앙 확인 중` |
| F4 포장 상태 확인 | `제품 교체 · 포장 상태 확인 중` |
| F4 중앙 처리 | `제품 교체 · 중앙 처리 중` |
| F3 사전 확인 | `포장 완료 · 현재 제품 집합 확인 중` |
| F3 내구 저장 | `포장 완료 · 중앙 저장 중` |

처리 중 상태줄에는 위 문구 뒤에
`통신 완료 전 추가 입력은 받지 않습니다.`가 붙습니다.

처리 중에 추가 입력을 시도하면 화면은
`이전 작업 처리 중 · 입력 보존`과
`통신이 끝나지 않아 이번 입력은 접수하지 않았습니다. 입력을 보존했습니다.`를
표시합니다. 이 경우 입력칸의 값은 지워지지 않습니다. 같은 바코드를 다시 찍지
말고, 처리 중 표시가 끝난 뒤 입력칸에 보존된 값을 확인하여 한 번만 제출하세요.

`PENDING` 또는 timeout이 확인된 경우에도 같은 PHS2·F3를 반복하지 말고 자동
재시도를 기다리세요. 이 문구는 기존 작업자 안내의 반복 금지 원칙을 그대로
유지합니다.

## 3. 완료·대기·충돌 안내

- `중앙 포장 확정 대기`가 보이면
  `저장된 포장 완료 기록을 복구하고 있습니다. 복구가 끝날 때까지 PHS2를 이동하거나 다음 포장을 시작하지 마세요.`를 따르세요.
- `중앙 포장 충돌 · 실물 작업 중지`가 보이면 실물을 구분 보관하고 화면 안내에
  따라 작업 리더 또는 관리자에게 중앙 상태 확인을 요청하세요. 저장된 로컬 완료
  기록을 삭제하지 마세요.
- `처리 상태 확인 필요`와
  `처리 상태를 확인할 수 없습니다. 추가 스캔을 중지하고 관리자에게 문의하세요.`가
  보이면 추가 스캔을 중지하세요.
- 처리 중 종료를 요청해 `처리 완료 후 종료합니다`가 보이면 작업이 끝날 때까지
  창을 강제로 종료하지 마세요.

## 4. 반복 금지와 실물 보존

- 이미 로컬 완료가 기록된 작업을 새 PHS2나 새 F3 입력으로 다시 만들지 마세요.
- `PENDING`/timeout은 완료 여부가 불명확한 새 작업을 만들라는 뜻이 아닙니다.
- 충돌·관리자 확인 상태에서는 DB, CSV, 현재 상태 파일과 outbox를 직접 수정하거나
  삭제하지 마세요.
- 입력이 접수되지 않았다는 안내와 입력칸에 보존된 바코드는 구분하세요. 현재
  Label_Match는 busy 거절 때 입력칸 값을 보존하므로 재스캔하지 않습니다.

## 5. M7 external capture bundle v1 계약

이 저장소는 별도 계약 사본을 정의하지 않습니다. 정본은
`E:/KMTech/production-readiness-20260830/HANDOVER/CAPTURE-BUNDLE-V1-CONTRACT.md`이며,
schema는 `M7 external capture bundle v1`, 앱 식별자는 `app=Label_Match`, 외부 앱
root는 `E:/requal-evidence/capture-bundle-v1/Label_Match/`입니다. 저장소의 기존
tracked 이미지는 삭제하지 않고 이력 자료로 보존하며, 현행 화면 증거는 승인된
external bundle로 대체 예정입니다.

필수 state ID는 다음 9개입니다.

1. `phs2_admitted_busy`
2. `phs2_rejected_input_preserved`
3. `f4_admitted_busy`
4. `f4_rejected_input_preserved`
5. `f3_admitted_busy`
6. `f3_rejected_input_preserved`
7. `central_submission_wait`
8. `central_submission_conflict`
9. `broken_fail_closed_warning`

조회는
`E:/KMTech/production-readiness-20260830/HANDOVER/HANDOVER-INDEX.md`에서
시작합니다. 그 문서가 게시한 immutable
`E:/requal-evidence/capture-bundle-v1/indexes/handover-index__<YYYYMMDDTHHMMSSZ>__<nonce8>.json`
receipt에서 `app=Label_Match`를 고르고, 항목이 가리키는
`Label_Match/<bundle-id>/manifest.json`의 `captures[].state_id`로 화면을
선택합니다. 승인 또는 custody가 미정이면 게시·교육·인계 화면으로 사용하지
마세요.

이 문서에는 raster, bundle-id 또는 나중에 생성될 digest 값을 다시 기록하지
않습니다. 그 값은 외부 bundle과 handover index에만 둡니다. `L-5`와 `L-6`의 제품
판정이 끝나기 전에는 capture tool의 release gate가 차단되며, BROKEN 경고 상태를
정상 화면처럼 간주할 수 없습니다.
