# 포장 앱 이름 등록 B

`stage_a=false`. 이름을 숨기거나 30일을 계산하지 않는다. 설정의 작업자 선택 옆 「새 이름 등록」 한 창에서 이름만 받는다. 승인·PIN·개인정보 입력은 없다. NFC와 공백을 정리하고 1–64자, 제어·경로·수식 시작 문자와 보호 관리자 입력을 검사한다. 「이름 #번호」의 번호는 선택 화면에만 쓰며 기록·CSV·전송 이름에는 붙이지 않는다.

작업자 행·임시 UUID·순번·요청 본문·request_id·action_at은 `app_settings.json` 옆 `roster.registrations.json` 한 envelope로 flush/fsync·원자 교체한 뒤 선택할 수 있다. 저장 실패면 입력을 남기고 다른 작업은 계속한다. 손상 파일은 `.bad-<고유값>`으로 보존하고 새 UUID로 다시 만들지 않는다. 회사 서버가 꺼져도 로컬 등록과 기존 웹 이름 선택은 된다.

기존 생산자 HTTPS/HMAC으로 v2 query/register를 뒤에서 호출한다. v2 query가 404/405면 v1 query를 사용한다. B 두 신호가 true이거나 `worker_roster_v2_stage_b` 표식이 있을 때만 register를 보낸다. 임시 ID 기록 역시 B 신호로만 전송하며 중앙 ID의 v1 신호는 그대로다. 재시작·재시도에서 원 본문·UUID·시각을 지키고 서명 nonce만 바꾼다.

503·429·5xx·끊김은 대기 요청을 남긴다. 설치 인증/현장 오류는 이번 전송 회차만 멈추고, 항목 오류는 다음 항목으로 간다. 409는 원 요청과 「관리자 확인 필요」를 보존하며 새 UUID를 발급하지 않는다. 같은 이름이면 한 번 확인한다. 같은 사람은 기존 UUID로 복귀하고, 미확정이면 create에 종속된 복귀 요청을 저장한다. 다른 사람이면 구분 이름을 받는다.

ACK와 모든 query의 자기 설치 temp_links를 내구 저장한다. 늦은 명단은 최신 상태를 덮지 않지만 불변 대응은 저장한다. DISABLED는 로컬 별칭·대기 복귀보다 우선한다. 서버의 최종 이름/번호는 선택 표시와 다음 트레이 신원에 쓴다. 진행 중 트레이·저장된 command의 임시 UUID/이름/본문은 바꾸지 않는다. 기존 설정의 작업 중 이름 변경 제한, 스캔·봉인 순서, LM-17, 관리자 PIN 흐름은 유지한다.

등록 HTTP는 배경 스레드에서 실행하고 응답은 현재 시도·로그인·현장·명단 객체를 확인한 뒤 writer 허가를 다시 얻어 적용한다. 사람 응답·HTTP 대기 중 허가를 쥐지 않는다. 실제 화면·회사 서버 확인은 별도 점검 대상이다.
