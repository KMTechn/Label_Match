## New decisions and uncertainty

SPEC.md D1–D8 explicitly identify index selection, strict parser/unknown-field
handling, numeric/resource limits, portable Windows path spellings/hardlinks,
PNG decoder details, error ordering, read-only/quiescent input scope and equality
choices. These are small fail-closed interpretation choices, not historical facts.
No original unknown reason code or check ordering is asserted. Every ordinary
outcome is bounded and deterministic for the same supplied bytes.

The fixed registry is literal. Runtime imports are Python standard library and
Pillow only: no app, builder, producer, server, Git object, sibling checkout or
describe-driven registry import. The independent fixtures duplicate the SPEC's
literal state sets and field expectations, assemble their own tiny PNG files,
and compute hashes without validator or producer helpers. Resealing recomputes
only parent byte hashes; it does not repair semantic mismatches. Single-defect
tests prove the named failure and restoration, instead of accepting any failure.

Consumer compatibility is complementary evidence, not the independent oracle:
the copied existing producer-based tests exercise the real materializer and
publisher boundaries with only documented local resolver adaptations. Original
test assertions and skip guards remain unchanged in scratch; all 15 selected
cases must actually execute, rather than count guard removal as success.
Integration in the repositories remains a separate future task. No real GUI,
network, server, publishing, build, install or FULL proof follows from these tests.
